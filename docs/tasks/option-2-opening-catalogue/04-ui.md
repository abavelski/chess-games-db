# O2-04 — Opening filters and labels; standalone catalogue release

Depends on: O2-03 API contract; use mocked/seeded enrichment without running O2-02. Read [shared rules](../README.md).

Deliver:

- Add an Opening control alongside current filters. Use a searchable hierarchy: family → line → arbitrarily deep sublines, with an “All lines” choice at each parent. Example: Sicilian Defense → Najdorf Variation → English Attack. Show game counts, an “Unclassified” choice, and a clear/reset action.
- Show the full selected breadcrumb and explain “Games reaching this line, including transpositions.” Selecting a parent includes its sublines. Changing parent clears incompatible descendants, resets pagination, and preserves other filters. Support keyboard navigation and accessible labels.
- Show each game's primary opening and variation in its list row; make the full path available if visually truncated. Show the name in the review header too. Keep original and derived ECO distinguishable when they differ.
- Unclassified games remain browsable. Legacy archives show existing ECO normally and a concise unavailable/unenriched state without broken controls. For partial coverage, show coverage/status and allow filtering classified games. Opening the archive again refreshes enrichment metadata.
- Back/Escape restores opening selection, existing filters, list page, scroll, and focus. Retain the compact games-only UI and offline operation.
- Document the migrate → download → enrich → reopen workflow and recovery/rebuild commands. No Explorer token or runtime network request is required.

Acceptance/tests:

- Desktop fixtures test family/line/subline selection, searching names, parent changes, clear, no results, combined book/year filters, pagination, list/review labels, and Back/Escape state restoration.
- Verify minimum desktop size, keyboard access, long names, legacy and unenriched archives, partial coverage, and hash-stale enrichment.
- Release gate: `npm test`, `npm run build`, `npm run test:desktop`, and preserved opt-in reader smoke. Demonstrate a fully usable app with **only O2-01–04 implemented**; no option-3 tables, credentials, or services.
