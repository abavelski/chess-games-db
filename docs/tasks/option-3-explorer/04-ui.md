# O3-04 — Optional reference evidence in game review and filters

Depends on: O3-03 API contract; use seeded evidence without O3-02. Read [shared rules](../README.md).

Deliver:

- Keep catalogue opening/line filters unchanged. Add optional reference-profile and “Minimum reference-book moves” controls only when applicable enrichment exists; display the chosen source and thresholds.
- In review, distinguish catalogue opening names from move evidence such as “Played in 42 master games.” Show count/share and snapshot date; visually mark the contiguous reference prefix and explain its stopping reason.
- Optionally add a compact reference-prefix summary to list rows. Avoid asserting theoretical correctness or novelty. Missing/partial/stale data reads “Unknown” or “Not enriched,” never zero evidence or an error blocking review.
- Display reference source, rating/speed/date settings, maximum indexed depth, and freshness where users inspect evidence. The renderer never requests tokens, fetches live statistics, or writes the archive.
- Document fetch/refresh/rebuild workflows and that snapshot evidence is not historical novelty analysis. Preserve the standalone option-2 experience on every supported archive without Explorer enrichment.

Acceptance/tests:

- Desktop fixtures cover profile selection, minimum-prefix filtering with opening sublines, list/review consistency, Back/Escape restoration, unknown evidence, and partially enriched archives.
- Test offline launch/review with cached results and no token; v3, catalogue-only v4, empty v5, and enriched v5 all remain usable.
- Release gate: shared checks plus option-2 release regression tests; live API access is not required. Verify original PGNs and catalogue classification are unchanged.
